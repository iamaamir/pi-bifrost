# Acceptance coverage map

This map catalogs evidence boundaries for PRD.md requirements R01–R17. A covered status means the acceptance command has a named case that checks that boundary. It does not mean the current candidate passed; read the ordered result for the candidate under review in screenshots/acceptance/<runId>/evidence.json.

Partial means named cases exercise only part of the requirement; the boundary column states the limit. Missing means no named result supports the requirement yet. Existing unit or integration suites still run through verify:release, but a suite filename or aggregate gate is supporting evidence only. Deferred records an accepted product-scope decision. A required case that cannot run is recorded as blocked in the run evidence and makes the run fail.

## Accepted scope limits

- Full phase timings remain deferred under ADR 0007.
- Strict boundaries follow ADR 0021; the broader direct-model fallback proposal is not part of this release.
- The only automatic replay exception is ADR 0023.
- ADR 0024 pauses the configured Pi provider ID. It does not infer a shared account or add live quota fetching.
- The opt-in live profile accepts exactly one explicit Pi model per run and permits only its built-in OpenAI, Codex, or Anthropic native HTTPS origin. Custom provider origins and local endpoints block before provider requests. Dynamic command or environment expansion in the selected credential/provider/model config blocks before SDK setup; isolated files expose only the selected provider/model. Provider requests use an exact-origin, per-model budgeted SSE transport with redirects rejected and auth/quota responses aborting pending work. Offline profile tests use fake transports only.
- First-use and manual init evidence follows ADR 0025; generated pools are provisional until probes finish.
- Image routing, general capability enforcement, thinking policy, live quota adapters, stable public API guarantees, and account-selectable dispatch are deferred or blocked external evidence gates. A live profile result never upgrades these claims automatically.
