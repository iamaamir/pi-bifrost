Bifrost

Automatically route each Pi prompt to a model based on task complexity, price, speed, or context length.

Features

🔬 Probe-first init

Tests every model with a real request before writing config. No dead providers, no phantom models.

⚡ Zero-token routing

7 selection strategies — cheapest, fastest, largest context — all metadata-based. Routing costs nothing.

📊 Production observability

Performance API traces, JSONL debug logs. Every decision timestamped. AI-parseable.

🎯 Direct model bindings

Assign specific models to specific prompts via regex rules. \bcommit\b → opencode/glm-5.1.

⚡ Inline override

Prefix any prompt with !frontier or !economical to force a tier for one message. No config change.

Install

pi install npm:pi-bifrost

What it does

You type a prompt. Bifrost inspects it — is this a complex task like debugging or architecture? Or something simple like formatting or a greeting? It classifies every prompt into a tier, then selects the best available model for that tier using configurable strategies. The model switches before your prompt is sent. You never touch /model.

🧠 Classify

LLM or regex reads your prompt and picks a tier.

🎯 Select

Strategy picks the best model: cheapest, fastest, largest context.

🔄 Switch

Model changes automatically before the prompt is sent.

Setup

One command. It probes every model you have access to, finds the ones that actually work, and writes a config.

/bifrost init

Say yes. Done. Bifrost is now routing every prompt.

Selection Strategies

How Bifrost picks from a tier's model list. Set globally or per-tier.

Available strategies for selecting a model from a tier
Strategy Picks
cheapestLowest input + output cost
cheapest_inputLowest input cost
cheapest_outputLowest output cost
largest_contextBiggest context window
randomRandom pick
first / fastestFirst in list (init orders by speed)

Config

Everything lives in .pi/bifrost.json. Editor autocomplete works in VS Code, Zed, Cursor.

Prefix any prompt with !tiername to force a tier for one message. Set "model": "provider/id" in a rule to bypass tier selection and route directly to a specific model.

{
  "enabled": true,
  "default": "economical",
  "strategy": "first",
  "categoryStrategies": { "economical": "cheapest" },
  "models": {
    "economical": [
      "opencode/deepseek-v4-flash-free",
      "lmstudio/openai/gpt-oss-20b"
    ],
    "frontier": [
      "opencode-go/glm-5.1",
      "opencode-go/grok-4.5"
    ]
  },
  "rules": [
    { "pattern": "\\b(debug|fix|implement)\\b", "model": "frontier" },
    { "pattern": "\\b(explain|format|hello)\\b", "model": "economical" }
  ],
  "classifier": {
    "enabled": true,
    "model": "opencode/mimo-v2.5-free"
  }
}

Built with

⚡ Zero-token strategies

All 7 selection strategies use model metadata only — no API calls, no tokens spent on routing.

📊 Probe-verified

Init tests every model with a real request. Only working models make it into your config.

🎯 Direct bindings

Route specific prompts to specific models via model: "provider/id" in rules. Bypasses tier selection.

⚡ Inline override

Type !economical <prompt> to force a tier for one message. Works in any chat.

🧠 Dual classifier

LLM reads your prompt for accuracy. Regex catches what the LLM misses. Direct bindings win both.

🔍 Debug logging

JSONL trace of every decision, timing, and model switch. AI-parseable. /bifrost debug for live state.
