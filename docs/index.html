Pi-Bifrost

A model-routing extension for the Pi coding agent. Pi-Bifrost classifies each prompt into a configured tier, then applies one selection strategy to the matching models available in Pi.

Install GitHub and documentation

How Pi-Bifrost routes a prompt

Routing has two stages: classify the prompt into a tier, then select one model from that tier. Classification can run with rules alone or use the optional LLM classifier.

  1. 1

    Check direct bindings

    A regex rule targeting an exact provider/id wins immediately. It bypasses tier classification and model-selection strategies.

  2. 2

    Check the classification cache

    A matching cached LLM classification reuses its tier and skips a new classifier call.

  3. 3

    Classify into a tier

    Classifier off

    1. Skip the LLM classifier.
    2. Use the first regex rule that matches the prompt.
    3. Use the configured default tier if no rule matches.

    No additional model call.

    Classifier on

    1. Send the current prompt and tier names to the configured classifier.
    2. Use the returned tier when it matches the configuration.
    3. On failure, try the next classifier, then regex rules, then the default tier.

    May use tokens and add latency on a cache miss.

  4. 4

    Select a model from the tier

    Tier patterns are resolved against Pi's available model registry. One configured strategy selects by cost, context window, list order, or random choice.

  5. 5

    Switch Pi's active model

    Pi-Bifrost activates the selected model before the prompt is sent. If no model matches or activation fails, Pi keeps its current model.

Controls

Probe at setup

/bifrost init sends a tiny request to supported OpenAI-compatible and Mistral models. Working results are used to build tier lists; unsupported API types are skipped.

Select from metadata

Choose by input cost, output cost, combined cost, context window, random choice, or configured list order. Policies can differ by tier.

Preview and override

Preview a route without sending. Type frontier debug this to force the expensive model for one message, or pin the active model until you run /bifrost unpin.

Routing diagnostics

Optional local JSONL logs record timing and routing metadata for troubleshooting. They are disabled by default and are not a hosted observability service.

Install

Install the package, then initialize it in Pi.

  1. 1
    pi install npm:pi-bifrost
  2. 2
    /bifrost init

Privacy and failure behavior

Classifier scope
The optional classifier receives the complete current prompt, tier names, and classifier instructions. It does not receive conversation history, prior messages, or tool output.
Local data
The cache may store normalized, sorted prompt words in .pi/bifrost-cache.jsonl. Debug logs contain routing metadata, timings, and prompt length, not the prompt body.
Classification failure
Pi-Bifrost tries the next classifier candidate, then regex rules, then the default tier. If nothing resolves, Pi keeps its current model.
Model failure
If no candidate matches or the selected model cannot be activated, Pi keeps its current model. Pi-Bifrost does not retry another routing candidate at send time.
Credentials
Registry models use credentials managed by Pi. A custom classifier endpoint is treated as an unauthenticated OpenAI-compatible endpoint.

Configuration and commands

A tier is a key in models, such as frontier. A route rule uses the property model: its value can be a tier name or an exact provider/id. There is no tier property on a route rule.

Configuration example
.pi/bifrost.json 
{
  "enabled": true,
  "default": "economical",
  "strategy": "first",
  "categoryStrategies": { "economical": "cheapest" },
  "models": {
    "economical": [
      "ollama/qwen2.5-coder:latest",
      "lmstudio/openai/gpt-oss-20b"
    ],
    "frontier": [
      "openai-codex/gpt-5.4",
      "opencode-go/kimi-k3"
    ]
  },
  "rules": [
    {
      "pattern": "\\b(debug|fix|race condition)\\b",
      "model": "frontier"
    }
  ],
  "classifier": {
    "enabled": true,
    "model": "opencode/deepseek-v4-flash-free",
    "method": "auto"
  }
}
Selection strategies
Pi-Bifrost selection strategies
Name Behavior
cheapest Lowest combined input and output cost
cheapest_input Lowest input cost
cheapest_output Lowest output cost
largest_context Largest context window
random Random available candidate
first First available candidate in list order
fastest Alias for first; init orders generated lists using one setup-time probe
